# 校验与发布门槛

## 工具实际检查

规范表齐全与主键唯一；每册一根；树无环／同册归属；节点区间正长和父子包含（提供区间时）；块唯一成员与标题归属；来源记录覆盖；片段引用、规范框与字符跨度；图片出现到资产／块的引用；图注与候选目标引用；资产路径与哈希；SQLite integrity_check；嵌入文件全量字节哈希；merge 源表逐行 EXCEPT 与数量精确并集。

报告 `passed` 仅代表上述技术门槛，不代表 OCR、图注语义、页图完整或人工准确率。

## 执行模型另需完成

- 把用户文件 inventory 与实际纳入册数、物理页清单、解析分段做覆盖核对，检查漏页及重复页。数据库内部自洽不能证明输入齐全。
- 对解析输出目录与文件白名单做差集，确认未引用原图亦保存。
- 若需“完整多模态来源包”，检查每一页有源预览或可恢复的来源，每册有源 PDF／获准的替代来源；不存在时标为部分来源包。
- 如有图像库可用，解码全部媒体并记录失败；原图视觉构件完整性需人工／视觉核查，文件哈希检查不能代替。
- 人工／视觉抽查跨页正文恢复、并列区域、缺章、图号冲突、地图图例、组合图和空表。不要在未运行时声称这些检查已通过。
- 跨页延续、表格行列、空间范围及原位的语义正确性不由当前通用脚本自动认证。

## 失败与续建

输入缺表／主键重复／丢图片／坏引用：停止该输出发布，保留输入，修复新工作副本后再跑。工具以独占创建拒绝覆盖已有交付；失败后的 `.partial-*` 工作目录保留供诊断，不冒充成品。

图注不确定但来源保留：可发布候选库，报告 unresolved 数。未完成的书明确列出，不把部分完成说成全部完成。外部解析任务不明时先恢复状态，不无界重复提交。

## GitHub 分发边界

只发布 Skill、原创代码、合成样本和文档。教材 PDF、原文、图片、数据库、解析响应、私有路径、密钥均不进入仓库。生成结果默认忽略，但发布前仍审查完整文件清单，`.gitignore` 不是保密证明。

创建本地仓库不等于远程上传授权。发布时确认账号／组织、仓库名和公开性，通过已有授权连接或用户在本机登录；不索要明文密码／令牌。代码许可证不授予教材内容的传播权。
