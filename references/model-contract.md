# 模型中立的标注／对齐协议

Skill 是执行流程，不是在线模型服务。宿主负责提供文件访问、代码运行及必要视觉能力；没有这些能力时，只能提出标注建议，不能声称生成了真实文件。本版本不内置任何模型 API 或自动多模型调度。

## 给执行模型的页包

包含：input_version、source_sha256、book_id、processing_pages、context_only_pages、固定 page/block/fragment ID、原解析记录、允许读取的页面图片／解析文本、目录锚点、相关规则及 schema_version。页包文件路径使用运行目录相对路径。

模板：

```text
按随附结构标注规则处理 processing_pages，只把 context_only_pages 当上下文。
保持原文、来源 ID 与已发布 ID。先定组织单元和教学容器，再定内部任务、块归属、成员顺序及图注。
不得按知识含义改编原位；不确定项保留候选与证据。
返回 schema 所需规范对象及 annotation_records，记录本次真实模型身份、版本（未知填 null）、run_id 与规则版本。
仅给简短可核查的理由；不要输出人工已确认状态。
新增对象使用本次命名空间临时 ID，保留来源区域以便稳定映射。不要凭空生成教材内容或图片。
```

调用端验证：输出 JSON 可解析；对象／证据 ID 来自页包或合法新增映射；重复 ID、越界范围、跨册误连、无证据补题名进入错误队列。截断响应不能当完整提交，缩小页包后在新运行记录中重试。

## 人工和不同模型怎样对齐

1. 冻结同一输入文件、块与页包；人工 A、人工 B、模型 M1/M2 各自结果独立保存。
2. 固定块任务共享 source IDs，直接比较类型／归属／图注目标；节点先按标题来源锚点和成员区域匹配，再比较父节点，避免用“同父节点”匹配而掩盖错误。
3. 端到端允许对象增删拆合，用来源区域、文本跨度、标题锚点建立映射；不因临时 ID 不同就判错，也不只按文本相同就判一致。
4. 对齐表记录 namespace、local_object_id、aligned_object_id、match_method、evidence_refs、status；不覆盖原始预测。
5. 人工辅助修正的结果与独立盲标结果分开。多数模型同意不是人工金标准，不能据此直接算“准确率”。

annotation_records 至少登记真实 producer_type（rule_engine/model/human）、对象、judgments、evidence_refs、run_id、手册/schema/提示词版本、review_status。具体参数只记录实际调用过的，不猜测服务默认值。

配置由助手编写、规则脚本逐对象生成标签时记 rule_engine，模型字段可为 null；不能写成每对象模型推理实验。

没有人工双标时报告待核数和技术覆盖；有人工标注时另行明确采样、匹配准则、分母和指标。已用于调规则的样本不称完全未见测试集。
